# macOS App

[返回文档索引](README.md)

原生 SwiftUI App 和 Go CLI 连接同一个 `gateway` 守护进程，共用配置、状态 API、日志和网络规则。服务已经运行时，从另一个前端启动只会连接现有服务，不会创建第二个数据面进程。

## 页面

- **网络总览**：可上下滚动的首页，顶部展示在线设备、本季度已记录的代理 / 直连流量、实时吞吐和全局出口健康；中间为连接拓扑，下方为最多三列的出口卡片。网络出口不再是独立菜单。
- **配置规则**：管理设备与域名分流、规则预设及自动学习；设备策略优先于域名策略。
- **设备接入**：设备流量排行、基于目标域名的服务识别、设备级默认/直连/代理/拒绝开关，以及通过 ping 探测候选 IP 的设备接入向导。
- **流量记录**：已响应、失败、无数据、拒绝和出口回退等连接结果，可按设备、出口、结果筛选并搜索，提供自学习记录入口。
- **设置**：接入与代理、外观、版本与更新、CLI 与 Agent、实时日志；在“CLI 与 Agent”导出外部 Skill。

App 采用统一的原生网络工作台，不再依赖经典 / PlayBridge 界面切换。规则编辑器支持拖动排序和 Clash 风格文本粘贴。已访问页面的搜索、筛选、滚动与编辑状态在切换时保留；隐藏页面暂停流量投影和拓扑动画，减少重复计算。

自动学习在代理模式且允许直连时，对未匹配明确规则的目标先尝试直连；直连失败或满足首响应超时重试条件后，代理收到响应数据才计入证据。24 小时内达到当前阈值（默认 1 次，可设为 1–10 次）后，按保存方式自动写入精确域名代理规则或等待确认。收到数据不等于业务成功，TLS 握手以外的请求数据不自动重放；明确规则和禁止直连设置优先。两路均失败时不生成规则。

“学习方案与设置”可调整开启状态、确认次数、自动保存、直连 / 代理等待、最大直连等待、冷却和临时记忆时间。设置不会追溯批量生成规则。旧版候选证据不混用，已保存的旧版直连规则保持原方向。

### 大量自学习记录

- 先区分 **待确认 / 已保存 / 暂停学习**；暂停学习不等于拒绝访问。
- 服务优先使用已保存的 `自动学习 · 服务名` 分组；连接观察作为补充，无可靠信息时显示“未分类”，不猜根域名或服务。
- 已保存记录按服务分段展示，并独立标明 **精确域名 / 域名及子域名等范围** 与 **代理 / 旧版直连 / 拒绝等路由**；服务、路由、范围和文字搜索可组合筛选。
- 每页 50 条，显示匹配数、总数与页码；大数量徽标缩写但保留精确提示。索引缓存、稳定标识和懒加载用于避免数千条记录同时构建视图，不裁剪实际保存的规则。
- 撤销仅移除对应的学习规则并同时暂停学习；恢复后重新观察，不立即生成规则。不要为减少条目而擅自合并成更宽的域名后缀规则。

设备临时保护以运行遥测 `device_adaptive` 的阈值、窗口、持续时间及设备 `until` 为准，不用固定分钟数推断恢复时间；保留显式设备策略和禁止直连要求。

外部 Agent 的安装与控制方式见 [外部 Agent Skill](agent-skill.md)。应用不再提供内置 AI 助手和独立出口健康页面。

## 局域网 HTTP 代理接入

1. 在“网络总览”选择本机 VPN 提供的 HTTP/SOCKS5 代理作为出口；若保持直连，设备也会通过直连出口访问。
2. 打开“设置 → 接入与代理”中的局域网 HTTP 代理配置，开启服务。默认端口为 **17894**，可自行修改。
3. 选择“无需认证”或“用户名和密码”，然后保存。密码留空可以保留已保存的密码；切换无需认证会清除接入凭据。
4. 在其他设备的 Wi-Fi 手动代理或浏览器代理设置中，填写面板显示的 **服务器地址** 和 **端口**。HTTP 和 HTTPS 使用同一个端口；启用认证时填写对应用户名和密码。

无需修改客户端网关或 DNS。服务支持 HTTP 请求及 HTTPS CONNECT 隧道，只接管遵循代理设置的应用流量，不承载 UDP。设备规则、域名规则和默认出口仍生效，访问记录与流量统计也会记录这些连接。服务监听 IPv4，接受私有地址、链路本地地址及本机连接；默认关闭。

认证采用 HTTP Basic，与上游代理认证相互独立；Basic 接入凭据应仅在可信局域网中使用。密码通过标准输入交给核心，保存在权限为 `0600` 的配置文件中，不出现在状态 API 或命令行参数中。保存后运行中的新版核心会热应用；端口冲突时保留旧监听并报告错误。修改端口或关闭服务会断开已有代理连接。

CLI 也支持 `gateway http-proxy set`，从标准输入读取 JSON，例如无需认证的配置：

```bash
printf '%s' '{"enabled":true,"port":17894,"auth":"none"}' | gateway http-proxy set
```

认证配置使用 `auth: "basic"`、`username` 和 `password` 字段；后续更新省略 `password` 时保留原密码。

## 主题

内置暖沙米、经典浅色、石墨深色和海雾蓝四套主题。主题会即时生效并由 App 自动记忆。

## 数据与隐私

- 服务名称来自网关观察到的目标域名，例如 YouTube 或 Nintendo，并不是远端设备的本地进程名。
- 连接历史只保存在内存中，最多 2000 条、保留 72 小时，不写入磁盘。
- App 通过当前出口访问 `ipwho.is` 以显示公网 IP、地区和 ISP，结果在内存缓存 30 分钟；失败不影响转发。
- fake-IP 映射会写入权限为 `0600` 的本机缓存，以便重启后恢复域名。它可能包含访问过的域名，不应公开分享。

## 安装

从 [GitHub Releases](https://github.com/Tght1211/lan-proxy-gateway/releases/latest) 下载 DMG，将 **LAN Proxy Gateway** 拖入“应用程序”后打开。DMG 内包含同版本的 `gateway` 核心，设置页也可以把 CLI 安装到 `/usr/local/bin/gateway`。

涉及网关防火墙规则、系统代理或开机自启时，macOS 会请求管理员授权。旧版核心仍在运行时，App 会提示使用当前内置核心重启。

## 本机构建

```bash
make build-app
make dmg VERSION=v0.1.0-dev
```

只有 Xcode Command Line Tools 时，`make dmg` 构建当前 Mac 架构；完整 Xcode 或 GitHub macOS Runner 会构建 universal App。

模型解码回归检查（不依赖 XCTest）：

```bash
macos/test-models.sh
```

如当前 macOS 27 SDK 缺少 `SwiftUIMacros` 插件，可临时指定本机已安装的 SDK：

```bash
swift build --package-path macos --sdk /Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk
SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk macos/test-models.sh
```

### 设备接入方式与流量拓扑

“接入新设备”默认提供面向 Switch / PS5 的 [代理 Wi-Fi 引导](hotspot-setup.md)，适用于通过网线上网的 Mac。系统设置负责首次开启共享，App 检测并接管热点，设备自动获取地址。网关接入、手动 HTTP 代理和自动代理 PAC 收在“其他接入方式”中。手动代理填写本机局域网地址与已保存的端口（例如 `192.168.12.100:17890`），启用认证时另填用户名和密码。

拓扑将网关接入与 HTTP 代理分为两条入口，显示各自活跃来源数和所选日期范围的累计流量，随后汇入相同的设备策略与分流规则。手动与 PAC 使用同一个 HTTP 代理入口，服务端无法区分客户端配置方式；访问记录也显示接入方式。通过 TCP 隧道连接时，设备来源显示隧道客户端 IP，无法从代理连接推断远端设备的真实 IP。

### HTTP 代理稳定性与扩展边界

HTTP 代理的回归测试覆盖：可选认证、HTTPS CONNECT 缓冲数据、半关闭后完整读取响应、HTTP 流式响应及时刷新、上游 HTTP/SOCKS5 握手取消、拒绝响应不阻塞、16 路并发上传下载的完整性，以及上游恢复后无需重启入口即可重新连接。运行 `go test -race ./...`。

后续穿透配置应独立于本地代理服务，记录传输协议、内网目标 IP/端口及公网入口地址。TCP 隧道可以将公网入口映射到此 HTTP 代理端口，并继续使用同一套认证和路由策略。UDP 隧道必须连接支持 UDP 的协议端点；当前 HTTP 代理不能直接承载任意 UDP 流量，也不能把 TCP 监听端口作为 UDP 代理服务使用。已有连接在上游 VPN 中断时可能断开，客户端需重新建立连接；恢复测试验证的是新连接能够恢复，而不是迁移已断开的连接。

### PAC 自动代理

设备可填写 `http://<本机局域网地址>:<HTTP代理端口>/proxy.pac`，例如 `http://192.168.12.100:17890/proxy.pac`。「设备接入」和代理设置提供复制入口，不需要额外端口。PAC 下载不要求认证，也不包含密码；实际代理请求仍按已保存的认证设置校验。自动代理模式的认证支持由客户端决定，无法认证时可改用手动代理。

PAC 将请求交给网关统一分流，不复制域名规则，也不添加代理失败后的客户端直连兜底。仅遵循代理设置的应用有效。通过 TCP 隧道访问 PAC 时，脚本使用请求中的外部主机和端口；隧道入口与代理端口必须是同一个映射。

### 流量历史与日期筛选

首页顶部展示紧凑实时吞吐与全局出口健康，出口卡片保留对应路径的响应状态和独立探测。全局摘要汇总已观察的出口，不保证每个目标都可用；当前核心只配置一个代理上游，不能把多个出口卡片解释成多个代理节点。季度指标只合计本季度已保留且已分类的代理 / 直连流量，旧版未分类流量不能反推归属。

拓扑及用量详情支持日期范围查询，点击设备数量查看全部设备的上传和下载累计值。首页滚动查看下方出口卡片；不再通过独立“网络出口”菜单访问。

核心每 5 秒原子保存 `usage-history.json`，正常退出再次保存。记录按本机日历日期、设备 IP、接入方式、实际出口、代理入口和目标域名/IP 汇总，不保存完整 URL 或 HTTPS 页面内容。旧版本已丢失的历史不能补回；异常断电可能丢失最后 5 秒数据。统计仅包含实际经过本网关的流量，设备更换 IP 或多个设备共用隧道来源会影响设备计数。

### 默认规则

新配置内置 14 组、76 条规则，保留精确域名、域名后缀和 IPv4/IPv6 CIDR 的原始类型及顺序。已有配置不会被自动覆盖；可在规则编辑器中按预设分组添加，已存在的同类型同目标规则不会重复插入。

### 本机管理接口认证

管理 API 除了绑定 `127.0.0.1`，还要求独立的 Bearer 令牌。核心每次启动会在配置文件同目录生成权限为 `0600` 的 `api-token`；CLI 和 App 自动读取。局域网 HTTP 代理凭据不能用于管理 API，HTTP 转发和 CONNECT 均不能绕过认证。手动调用 API 时应从该文件读取令牌，勿复制进日志、诊断快照或 Skill 包。更新核心时应同步更新 App。

App 中更换代理出口、切换直连使用 `gateway egress`，不修改 Mac 的系统代理或 DNS。需要修改 Mac 系统代理时，使用明确的 `gateway system-proxy` 命令。

### 按设备核对代理用量

「设备接入」顶部显示今日当前代理入口（例如 `127.0.0.1:7897`）的上传、下载、合计，并对照本机直连量。点击「查看设备与域名明细」或设备 IP，按设备、日期、代理入口、服务/域名筛选。默认查看当前代理入口的代理记录；「直连」可核对普通宽带访问的域名。

统计使用已建立连接的实际出口；代理失败后回退直连计入直连，代理入口取连接时的上游地址，不随后续配置更改。旧版只有总量的数据标为未分类，不能反推代理用量。域名每日汇总重启保留，逐条连接记录仍只保留当前及近期数据。流量为本 App 转发字节，不包含 TCP/IP 开销、代理握手或 Mac 其他应用的代理流量，不等同于代理服务商账单；无法统计绕过本 App 的直连流量。设备按 IP 归属，DHCP 地址重新分配时需留意混淆。
