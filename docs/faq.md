# 常见问题（v4）

**Q：设备改了网关后完全连不上网？**
> 按顺序检查：① `gateway status` 确认 running=true；② 设备的**网关和 DNS 都**填了电脑的 IP（只改网关不改 DNS 等于没接入）；③ 设备 IP 前三段和电脑一致（如都是 `192.168.1.x`）；④ `sudo gateway restart` 重启一次；⑤ 看 `~/.config/lan-proxy-gateway/gateway.log` 有没有报错（比如 53 端口被占）。

**Q：只改网关不改 DNS 行不行？**
> 不建议。按 `gateway status` 打印的设备参数，把网关、DNS 1 和 DNS 2 都填成本机 IP；设备不允许两个 DNS 重复时，DNS 2 才留空。默认不会劫持设备发往其他 DNS 的查询。

**Q：日志里的“fake-ip 映射缺失”是什么意思？**
> 设备仍在连接以前解析到的 `198.18.x.x` 虚拟地址，但 gateway 已找不到它对应的原始域名，因此为避免连错目标而主动断开。新版本会把映射以 `0600` 权限持久化并保留 7 天，同时对重复警告限频。首次从旧版升级时没有历史缓存，设备可能仍需重新连接一次 Wi-Fi；之后 gateway 重启会自动恢复映射。

**Q：配了上游代理，国外网站还是慢？**
> 那是上游代理的节点问题，跟本工具无关——去你的 clash / sing-box 里换节点。本工具只负责把流量原样送过去。

**Q：国内 App / 网站会变慢吗？**
> 取决于你上游代理软件的分流规则（clash 通常国内直连）。本工具不做分流，只做"把流量交给上游"这一件事。如果上游配的是全局代理，国内流量也会走代理。

**Q：游戏联机 / 语音通话会走代理吗？**
> 不会。UDP 没有代理路径：QUIC(UDP/443) 在代理模式下会被拒绝、让浏览器回退 TCP；其余 UDP（游戏、语音）直连。NAT 类型与直接把网关指向路由器基本一致。

**Q：Apple TV 看 Netflix 地区不对？**
> 在你的上游代理软件里切换支持流媒体解锁的节点。本工具不挑节点。

**Q：本机（跑 gateway 的电脑）会被代理吗？**
> 启用“系统代理 / LAN 出口”后，本机应用和旁路由设备都会使用同一个代理地址；关闭后旁路由切回直连。规则与节点由该地址背后的代理软件处理。

**Q：Windows 上能用吗？**
> 目前不支持。项目只构建 macOS 和 Linux 版本，Windows 适配留待后续设计。

**Q：能装在普通路由器 / OpenWrt 上吗？**
> 当前不支持，也不作为部署目标。本程序不内置代理节点，普通路由器还要额外安装代理软件，并涉及 fw4/nftables、只读文件系统等适配。推荐使用低功耗 Mac mini 或完整 Linux 小主机，并连接已有的 Clash/sing-box 代理端口。

**Q：需要 sudo 是什么意思，安全吗？**
> sudo 是管理员权限。绑 53 端口、写 iptables/pf 规则、开 IP 转发都是系统级操作，必须有 root。程序开源，防火墙规则只打 `lan-proxy-gateway` 标记，stop 时按标记精确拆除。

**Q：和软路由比有什么优缺点？**
> | | LAN Proxy Gateway | 软路由 |
> |---|---|---|
> | 成本 | 利用现有低功耗电脑 | 需要另购设备 |
> | 上手难度 | 几条命令 | 刷固件 + 配置 OpenWrt |
> | 稳定性 | 依赖电脑保持开机 | 专用设备，更适合 7×24 |
> | 代理协议 | 交给上游软件（clash/sing-box） | 通常一体集成 |

**Q：关掉网关后，其他设备怎么恢复上网？**
> 把设备的网络设置改回"自动获取(DHCP)"，或忘记 Wi-Fi 重连。`gateway stop` 会自动拆除防火墙规则并回滚它改过的系统状态（ip_forward / pf），电脑本身无需任何恢复。

**Q：旧版配置还在，升级 v4 会怎样？**
> 第一次运行会把它备份为 `gateway.yaml.pre-v4.bak` 并重新走初始化向导。旧版订阅/节点/规则功能在 v4 里没有了——把这些交给 Clash/sing-box，再把它的 HTTP/SOCKS5 端口配置为代理端点。
