# 常见问题：按你遇到的现象排查

[项目首页](../README.md) · [图文手册](user-guide.md)

先确认自己用的是热点、HTTP/PAC，还是静态网关；三种方式的设备设置不同。实在无法联网，先按 [恢复网络](user-guide.md#stop) 切回原网络，再继续排查。

<a id="open-app"></a>
## 下载了，不能安装或打开

**附件太多，选哪个？** Mac 新手选 `macos-universal.dmg`；M 系列和 Intel 通用。手机、电视、游戏机不安装网关。Linux 选匹配架构的 CLI。见 [完整下载表](download.md)。

**App 提示系统版本不支持？** 图形 App 要求 macOS 13+。`darwin` 是 macOS，`linux` 不是 Mac 版本。

**macOS 提示无法验证开发者或无法检查恶意软件？** 先确认下载来自本项目 Release，并可对照同版本 `SHA256SUMS`。信任来源后，可按 [Apple 官方打开说明](https://support.apple.com/zh-cn/102445)，在尝试打开后进入“系统设置 → 隐私与安全性”，查看该 App 的“仍要打开”选项。不要为安装一个 App 关闭整台电脑的安全检查。若明确提示恶意软件或文件损坏，停止使用该副本并重新核对来源、下载和校验结果。

**更新提示无法安装？** 把 App 从 DMG 拖入“应用程序”，从那里启动后再更新。不要从只读 DMG 内运行。

## 网关核心启动失败

先看错误文字，再看 **设置 → 实时日志**。常见原因有管理员授权未完成、监听端口被其他程序占用、网络接口未就绪。记录具体端口和错误，不要直接关闭整个防火墙或删除配置。

CLI 用户先执行 `gateway status` 查看配置和状态；日志路径以实际输出为准。修改后才需要再次启动，查看日志不需要重启核心。

## 测试上游代理失败

依次核对：

1. 代理软件是否运行，且它本身可以访问目标网络。
2. 类型是否匹配：HTTP CONNECT / SOCKS5 / 混合端口的实际协议。
3. 地址和端口是否来自代理软件；不要填订阅 URL、控制器 API 端口或本网关的共享 HTTP 端口。
4. 远端代理地址能否从网关主机访问，是否有额外认证要求。

测试代理成功之后，还需要点击“应用代理”保存；有代理地址不代表它一直可达。

## 找不到 Mac 热点

先检查 Mac 是否**有线联网**，Wi-Fi 是否打开，系统“互联网共享”是否真正开启；App 的热点名称备忘不会创建热点。共享来源应为联网的以太网，目标为 Wi-Fi。

如果只有部分设备找不到热点，可在系统实际提供的选项中尝试其他信道或 2.4 GHz。改信道前需要关闭共享，改完重新开启，所有热点设备会短暂断开。见 [热点步骤](user-guide.md#wifi)。

## 连上热点却没有代理效果

系统热点与 App 接管是两个步骤：检查 App 是否显示 **热点接管已开启**。设备 IP/DNS 应自动获取、代理关闭；不要填写静态网关教程里的地址。

在“流量记录”选这台设备并查看新连接。分流允许部分目标直连，因此“能上网”和“某个目标已走代理”要分别验证。没有记录时，检查是否连错路由器 Wi-Fi，或被已有筛选条件隐藏。

## HTTP / PAC 配好后打不开网页

- 服务器必须是 **网关电脑的局域网 IP**，不是手机上的 `127.0.0.1`。
- 端口必须与 App 保存后的监听端口一致。默认是 `17894`；截图里的 `17890` 是自定义值。
- 页面应显示“正在监听”，只拨动开关而没保存不算完成。
- 确认设备和主机互相可达；访客 Wi-Fi 的客户端隔离可能阻止互访。
- 启用认证后检查用户名、密码和客户端认证能力；PAC 能下载不代表代理认证已通过。
- 某些应用不使用系统代理，只测试浏览器成功不能证明所有 App 都会走代理。

HTTP/PAC 不需要修改设备的 IP、网关和 DNS。

## 静态网关配置后完全断网

先恢复原网络，再核对主机是否运行、设备与主机是否同一实际子网、静态 IP 是否冲突、掩码是否正确，以及网关 DNS 是否可达。`24` 和 `255.255.255.0` 只是常见示例，不适用于所有网络。

默认静态接入没有 DNS 劫持；依赖网关 DNS 还原域名时，应把设备 DNS 指向网关主机，并确认网关 DNS 已启用。只改网关、仍用其他 DNS/DoH，可能导致域名规则无法命中。见 [完整静态接入说明](user-guide.md#static)。

## 访问记录显示“已响应”，但应用仍然报错

“已响应”只代表目标回了数据，可能是登录失败、地区限制、验证码或其他业务错误。网关不解密 HTTPS，不能判断账号是否登录成功或视频是否可播放。最终以设备上的实际使用结果为准。

只有部分网站异常时，查看对应域名、实际出口和失败详情，再检查本网关规则与上游软件的节点/规则；不能把所有慢连接都归因于上游。

<a id="gaming"></a>
## 能进商店，但游戏联机、语音或 NAT 不理想

本项目主要处理 IPv4 TCP，没有通用 UDP 代理。启用阻止 QUIC 时，UDP/443 受限以促使客户端回退 TCP；其他游戏/语音 UDP 通常仍走直连，具体还受设备策略和防火墙限制。

热点共享会增加 NAT 层级，公网环境、路由器、防火墙、运营商和游戏服务都会影响联机。不能承诺 NAT 固定为 A/B，也不能认为换代理节点必然改善 UDP。可先对比直接连接原路由器时的结果，再定位问题。

## 为什么“设备直连”了 / 规则没生效？

先看设备策略，再看域名/IP 规则的全局顺序；设备策略优先，其他规则首条命中。确认改完点了“应用规则”，并发起**新连接**。

自动学习只处理符合条件的未匹配目标，不覆盖所有明确规则；设备临时保护也可能影响出口，其阈值和恢复时间以实际运行状态为准。不要照旧文档假定固定 15 分钟。

## 自动学习很多条，能一键删掉吗？

先按服务、方向、范围搜索和分页。每条精确域名有自己的匹配范围，不要只为减少数量把它们扩大成域名后缀规则。“撤销并暂停学习”会移除相应学习规则；“暂停学习”不是禁止访问。详细含义见 [自学习](user-guide.md#daily)。

## 日志里的 fake-IP 映射缺失是什么意思？

设备仍连接先前解析的虚拟地址，但核心找不到对应域名时，会拒绝猜测目标。先让设备断开重连网络或重新发起解析；不要手动把 `198.18.x.x` 当真实公网地址加入规则。新版核心会持久化映射，但历史丢失的数据无法凭空恢复。

## 关窗口后设备仍能上网 / 删除 App 后服务仍在

界面与后台核心分开。要停用，从右上角 **… → 停止核心** 操作，并按需要关闭开机自启。使用热点时，macOS 互联网共享也是独立开关。先给设备恢复原网络，再卸载，见 [停止与恢复](user-guide.md#stop)。

## 是否会改 Mac 自己的系统代理？

App 的代理出口配置和 `gateway egress` 调整设备转发出口，保留 Mac 系统代理与 DNS。`gateway system-proxy` 是另一组明确修改 macOS 系统代理的高级命令，不是日常共享的必做步骤。

## 更新后怎么还没有新功能？

确认 **App 与运行中的核心** 都已更新。App 下载完后若提示“更新并重启核心”，还需执行这一步；重启短暂中断连接。Agent 用户同步更新 Skill，CLI 用户核对 `gateway --version`。不要删除配置来尝试修复版本不一致。

## 怎么提供有效的反馈？

提供版本、主机系统、接入方式、设备类型、出错时间、错误文字及脱敏后的单条连接截图。通过“设置 → 实时日志”查看相同时间附近的错误。不要提交密码、完整订阅、`api-token` 或含凭据的配置文件。
