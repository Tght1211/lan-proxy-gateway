# LAN Proxy Gateway 原生改造

以用户确认的 lan-proxy-gateway-demo.html 为交互基准，产品名称唯一，取消双界面模式。保留现有 Go 核心、CLI 和 SwiftUI 技术栈，不把演示 HTML 或示例数据嵌入产品。

## 页面与边界

- 网络总览：真实设备 → 接入方式 → 热点网关／LAN 入口 → 设备策略 → 域名规则 → 出口。节点均以 sheet 编辑；只在总览出现。连接采样后播放，默认状态配色，彩色色系按域名稳定映射，图标线条短动画，无矩形发光。首字节数据不足不伪造响应毫秒数。
- 网络出口：并入总览拓扑下方，紧凑卡片一行最多三个，窄窗口两列或单列；代理、直连、拒绝保留编辑／探测／明细入口，不再提供独立导航菜单。多代理池仍属于后续范围，当前不以演示 A/B/C 冒充真实功能。
- 配置规则：代理规则、自学习两个 tab，默认规则。复用列表／文本编辑和分组排序；显式规则优先于自学习。自学习配置与学习记录独立页面内呈现。
- 设备接入：Wi-Fi、静态 IP、PAC、HTTP 四个 tab；Wi-Fi 优先，三步简短指南，通用设备／游戏主机，频段、硬件地区建议；网络名默认 GrandLine，密码备忘使用 Keychain，不修改系统 Wi-Fi。
- 流量记录：复用真实连接表与筛选，保留应用归类、设备、出口、结果和流量；不重复总览吞吐图。
- 设置：功能与接入、通用、版本、CLI 与 Agent、运行日志；控制操作走现有接口，可用性由运行态确认；不提供保存后无效的假开关。配置与日志地址来自核心。

## 结构

导航与外壳独立；NetworkPresentation 为 Foundation-only 的纯投影层；NetworkTopology 只绘图与发出用户意图；NetworkSheets 集中对应节点 sheet；各页面组合现有业务组件。AppModel 继续负责命令与状态刷新，GatewayClient 负责 CLI/API。协议模型保持向后解码兼容。

## 验收

Swift 构建、模型回归、Go 全量测试；真实数据缺失显示空态，不展示样本；连接动画去重、重启重置、有界缓存；未知入口不猜测；停止／失败不能显示正常。保留用户未提交更改，不自动提交混合改动，不自动重启正在共享的网关。

## 当前交付与待扩展

已接入六模块原生界面、图标拓扑模态路由、首响应耗时、有界延迟回放、自学习参数保存和运行时应用、规则编辑冲突保护、Wi-Fi备忘与五类设置。Go核心仍使用一个上游代理；代理池/多源/显式兜底链、热点与静态网关同时透明接管、App原位升级属于待扩展能力。当前不会在产品中展示虚构的代理B/C。

学习等待参数：direct_wait_seconds、proxy_wait_seconds、max_direct_wait_seconds、cooldown_seconds、memory_minutes，分别默认5/5/30/30秒及10分钟。CLI通过 gateway learning configure '<JSON>' 保存，与UI共享状态文件。旧核心没有这些字段时UI禁用参数调整，仍可配置确认次数及记录方式。

首响应耗时 response_ms 表示第一段转发载荷至第一段上游数据的间隔，不含初始拨号；不把它标为ping或业务成功。HTTPS业务内容不解密。

构建验证使用 SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX15.2.sdk。原生预览位于 dist/LAN Proxy Gateway Native Preview.app；现有后台网关不自动重启。

## 设计稿还原补充（2026-09-30）

统一原生视觉组件集中在 StudioDesign.swift：Bare outline icons、Tab、按钮、下拉框与表单字段。Graphite/Light 采用演示稿的最终色板、14pt 卡片圆角、22pt 内边距。侧边栏为手工按钮导航，选中态为青绿色浅底；核心操作收进工具菜单，顶部保留出口状态。总览为顶部摘要与横向图标拓扑；出口为双列卡片；规则/设备/设置使用统一 Tab。

设备可见性按实际正字节传输时间 last_traffic_at 计算，不使用连接打开/关闭时间。超过10分钟为灰色、超过24小时不显示；新流量恢复显示。保留设备名称、规则和历史流量，仅隐藏当前拓扑/接入列表条目。旧核心未返回该字段时通过累计字节变化维护观察时间，避免轮询刷新活跃时间。

设备识别采用最近30分钟内的数据响应和多个平台信号。Google Play/Heytap/移动推送归为手机，系统更新/Steam客户端归为电脑；微信等跨平台服务阻止误判主机，单一游戏商店访问不识别为PlayStation。平台证据冲突显示未知，用户手动命名始终优先。

## 总览紧凑化与流光（2026-10-01）

稳定性和吞吐并入顶部摘要：保留近5分钟探测可用率、小型时间条、最近探测耗时，以及近1分钟下载/上传迷你曲线；去掉总览底部的大卡片、图表坐标轴和重复说明。较窄窗口自动换为两行。探测时间条仍可点击查看记录，数据边界说明移入悬停提示。

流光不提供暂停或关闭开关，跟随真实连接自动播放；系统“减少动态效果”只显示静态结果。色系保存在本机 networkFlowPalette，可在航路标题旁或设置中切换纯色状态、缤纷、海洋、极光、落日。纯色状态正常为绿色，首响应超过500ms为黄色，连接错误或拒绝为红色，等待/无数据为中性色；彩色色系正常响应按域名稳定取色，慢响应和错误仍优先使用黄/红。

互联网节点上方显示当前采样连接的域名和首响应耗时，结果短暂保留，多个请求不叠字。无耗时数据不补造；等待、拒绝、无数据、失败展示对应状态，拒绝结果停在拒绝节点。发送数据、收到响应和最终失败分别去重回放，连接关闭不会重复播放已经响应的结果。首响应仍不等同于HTTP业务成功。

布局精修：顶部计数字段采用窄列、趋势采用弹性宽列，指标数值与趋势区统一高度并用淡分隔线分组；运行范围等说明置于数值下方。底部仅保留紧凑状态图例；流光选择器采用统一菜单按钮。设备按活跃状态与IP自然顺序排列，不随每次流量轮询改变位置。界面改动必须同步替换并重签名当前预览App、重新打开界面程序；不默认重启后台核心。

## 自动撑满与文字上浮（2026-10-02）

总览以窗口可用高度为最小内容高度，摘要保留自然高度，航路图填满剩余空间，节点与曲线随图的高度舒展。移除四台设备上限，展示全部可见设备；设备增多时按至少96pt节点间距提高图的最小高度，超出窗口后由整个总览页纵向滚动，不在卡片内部建立独立滚动区。设备保留和隐藏规则不变。

设备策略、流量规则以及目标连接结果恢复缓慢上浮与渐隐，同一节点仍只显示最近一条，避免重叠。系统减少动态效果时结果保持静态可读；不伪造连接、结果或耗时。

## 滚动总览与出口摘要（2026-10-02）

替代前述自动撑满方案：首页使用一个纵向滚动区，依次展示顶部摘要、自然高度的连接拓扑、出口卡片。拓扑不再铺满窗口，设备数量较多时仍按节点间距增长，由整个页面滚动。出口卡片不另设内层滚动。

顶部按在线设备、流量构成、实时吞吐、网络出口健康排列，移除活动连接计数。流量构成按本季度截至今日保留的 usage_history 拆分代理与直连；历史未标注出口的流量保留为未分类，不反推或冒充直连。宽窗口优先给流量构成空间，窄窗口自动换行。

全局健康汇总真实配置的代理和直连，拒绝规则不计入。当前出口的新鲜探测和各出口最近五分钟的真实连接响应分别提供状态；未知、停止与异常不能显示正常。顶部不显示单一出口延迟，历史条仅回看真实连接响应；各出口卡片只展示自身独立探测，没有探测的出口明确留空。当前核心仍只支持一个代理源，不伪造多出口监测覆盖。

## 导航切换性能（2026-10-02）

主导航按需挂载并保留已访问页面，最多缓存现有五个模块；切换不销毁滚动位置、筛选、页内选项或规则草稿。隐藏页不可交互且从辅助功能树隐藏，切换仅做120ms透明度过渡，系统减少动态效果时不做过渡。主题切换仍按既有机制重建界面。

拓扑页隐藏时暂停时间线并清空流光回放，重新进入时以当前记录建立基线，不回放隐藏期间积压的数据。每帧绘制复用本次页面计算的节点和连线，不反复生成拓扑。全局出口健康缓存当前状态和历史条，隐藏时不扫描连接，返回时同步。流量记录把搜索、设备／出口筛选、结果计数和响应率合并为一次扫描并缓存投影；仅在页面可见且数据、标签或筛选改变时重算，重新进入时同步最新数据。

性能采样补充：仅验证导航功能不足以证明流畅。五秒主线程采样中，出口卡片 body 占据主要时间；历史筛选逐条调用 usageDate，导致大量日期格式器创建。出口今日统计改为每次可见数据刷新的一次聚合，卡片直接读取缓存；季度统计同样缓存并单次扫描。usageDate 改用本地时区的公历日期组件，保留 yyyy-MM-dd 协议格式，并覆盖跨时区、跨年和闰日回归。出口健康选取最新响应改用一次遍历，不生成中间观察数组；隐藏页不计算这些投影。

修复前已加载五个模块的预览进程，两次两秒区间 CPU 采样为83.1%和100.4%。同一个未开启编译优化的基准程序使用5000条合成历史记录，分别执行原先四次日期筛选和新单次汇总，三次中位耗时为305.894ms与1.573ms，代理／直连字节及连接计数全部一致。这是统计函数基准，不是整页帧率或实际进程 CPU 的修复后测量；真实界面仍需解锁后重载，并在访问相同模块后复测。

2026-10-03 解锁后重新启动已部署前端，访问相同五个模块后回到总览，三次两秒区间 CPU 采样为46.8%、54.0%、57.2%。后台网关未重启，真实流量和系统负载并非固定输入，因此只说明本次实测占用降低，不代表固定帧率或所有场景流畅。新的五秒采样主要落在拓扑时间线触发的 SwiftUI/AppKit 布局与提交；进一步将静态连线、列标题和节点坐标移出逐帧时间线，并通过可比较的节点标签隔离未变化的图标与文字。保留30Hz流光、节点点击与响应颜色；该后续重绘优化需要再次重载测量，不能沿用前述 CPU 数字作为其结果。

后续重载实测表明，仅隔离节点标签仍有57.3%–61.7%的占用，不能宣布此步骤解决了卡顿。继续将所有节点按钮和文字布局移出时间线；动画层只使用 Canvas 绘制粒子、节点轮廓和浮动结果。图标坐标使用静态布局锚点，复用 StudioIcon 的原有轮廓，不改变节点位置、点击区域或配色含义；图标两种轮廓在布局变化时生成，浮动文字以有界连接集合生成可复用符号，保留单行截断与响应结果。辅助功能仍可读取节点和最近采样连接。

最终预览进程确认启动于最新二进制部署之后。访问相同五个模块后回到总览，五次两秒区间 CPU 为21.9%、42.9%、43.0%、24.3%、44.6%；这是动态真实流量下的短时进程采样，不是固定输入基准或帧率测量。实机验证首页滚动到底后切换规则页再返回，滚动条仍为1；出口卡片可读且侧栏无独立网络出口菜单。流量记录搜索 google 后由2000余条缩小到516条，切换页面后搜索保留，测试结束清空搜索。构建、模型回归、展示模型回归和签名验证通过；不改网关配置，不重启后台核心。

## 大规模自动学习记录

自动学习入口及数字保持单行；超过千条使用 k / m 紧凑计数，悬停和辅助功能保留精确数量。连接结果筛选在较窄窗口可横向滚动，不再压缩学习入口或响应率。

学习详情支持待确认、已保存、暂停学习三个状态，按域名或服务搜索，每页最多显示50条。分页只限制界面显示，不截断、删除或修改后台学习规则。候选记录按最近观察排序，其余按域名稳定排序；相同记录跨轮询解码保持稳定标识，重复条目仍具有不同标识。后端动作继续使用原域名，保存条件与撤销／暂停／恢复语义不变。

服务名称先对连接做一次索引，学习记录采用缓存投影，不再逐域名反复扫描连接或按服务对整个候选列表反复过滤。数据未变不重新排序；隐藏页不构建索引，搜索、切换状态后回到第一页，记录数量变化时自动收敛到有效页。覆盖10000条规则的完整分页、不丢失不重复、大小写搜索、稳定标识、重复记录、空数据、页码越界和实时缩减回归。

分类将状态、服务、路由和规则范围分开：服务优先采用持久化的“自动学习 · 服务名”，当前连接元数据只作补充；无可靠分类时保留“未分类”。已保存记录按服务分段展示，服务筛选附精确计数，路由与范围可组合筛选。精确代理规则、旧版直连与域名后缀规则不会混为同一语义；暂停观察也不等于拒绝访问。保留原始 group 供搜索与显示，不根据最后两段域名猜测服务。

官方导出 Skill 同步这些分类语义及当前 CLI、认证和接入方式。只读脚本在本地读取完整 agent snapshot，再输出有界摘要和最多100条的分类分页；修改路由时仍保留本地全量规则，分页内容不得用于全量替换。导出包含静态脚本与参考，不携带用户配置、令牌或诊断数据。
