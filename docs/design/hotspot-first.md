# PlayBridge 界面模式

## 本轮落地

用户确认后已接入原生 SwiftUI App。项目与核心继续使用 LAN Proxy Gateway 名称；PlayBridge 是同一 App 的交互模式，默认仍为经典界面。首次邀请可关闭，两种界面都能从设置切换。切换只持久化界面偏好，不写网关配置、不调用启停命令、不重启网络。

PlayBridge 提供热点、设备、流量、加速源、设置五个入口。首页用可点击拓扑表达网络来源 → Mac 热点 → 游戏设备；不显示虚构设备、地区节点或延迟。三步引导依次完成系统共享、自备代理（可选）、主机接入和显式开启接管。采用浅蓝色原生卡片、清晰侧栏与系统控件，保持经典主题独立。

分流规则与高级工具默认不展开，在设置中按需显示。开关只控制入口可见性；已有规则和功能不因隐藏入口而关闭。高级设置继续提供原有管理工具。

## 产品与能力边界

App 是已有 Mac 网络与游戏设备之间的桥梁，不提供 VPN、节点、订阅或保证降延迟。直连模式也可开启热点接管。核心已有 DNS TTL 缓存与多上游并发查询；本轮展示这些基础能力，没有新增无线驱动优化或宣称对局 RTT 改善。

macOS 负责 Wi-Fi、DHCP 与共享网络；Go 核心负责接管、转发、DNS、分流和计量。当前不拆分项目，也不提供虚构的按需组件下载：基础热点管理仍依赖同一核心。未来只有出现足够大且可独立维护的模块时，再考虑签名、版本兼容、离线回退与按需下载。

目前主要处理 IPv4 TCP，未接管的 UDP 与绕过核心的流量不进入这些统计。热点减少静态地址配置错误，但不能保证无线链路比有线或手动网关更稳定。

## Wi-Fi 引导

沿用已有港版 / 日版 / 美版建议，并加入其他地区、PS5 / Slim、PS5 Pro、Switch / Lite / OLED、Switch 2 选择。这里只提供兼容性建议，不构造未经验证的机型支持矩阵。

- 默认港版指硬件销售地区，不是账号区服，也不改变 Mac 无线地区。
- 近距离先尝试 5 GHz 信道 36，其他候选为 40 / 44 / 48；必须以 macOS 当地实际选项为准。
- 兼容性优先或发现不了热点时尝试 2.4 GHz 信道 1 / 6 / 11。
- Switch / Lite / OLED 需要兼容 WPA2 的安全模式；不能默认所有设备都支持 WPA3-only。
- 选择建议不会改系统信道，不宣称可同时创建双频热点。更改系统信道可能断开当前连接，需在主机实测。

依据：[Apple 互联网共享](https://support.apple.com/en-ng/guide/mac-help/mchlp1540/mac)、[Nintendo Switch 无线连接常见问题](https://www.nintendo.com/en-gb/Support/Nintendo-Switch/Nintendo-Switch-Internet-Connection-FAQ-1500174.html)、[Nintendo 香港安全模式说明](https://support.nintendo.com/hk/switch/qna_sub/34151.html)。这些资料不等于所有地区与机型的完整信道认证表。

## 数据与状态

成功状态沿用 `HotspotControlState`，由运行中核心的 `enabled && applied` 确认。发现系统热点不等于 App 已接管。停止接管保留 macOS 互联网共享。

计量从 `usageHistory` 中筛选 `gateway` 入口和当前热点 CIDR，并排除网关自身；首页按本地日期显示总量、代理和直连。未分类历史记录计入总量，因此代理＋直连可能小于总量。历史记录没有持久化热点来源标记，当前网段复用时可能归入同网段旧记录；界面已标注此范围。

吞吐曲线按实际采样间隔计算累计上传／下载差值，保留最近五分钟。首次采样、日期或网段变化、核心重启、计数回退、超过 15 秒的采样空档以及读取失败均清空基线，不生成负速率或虚假峰值。重开 App 后不会伪造之前的曲线。统计缺失显示不可用或等待采样。

## 验证

- 使用 macOS 15.2 SDK 的 Swift 原生构建通过。
- `macos/test-models.sh` 覆盖模式默认值、网段／入口／日期过滤、真实时间间隔速率、重启／计数／日期或网段重置、采样过期。
- 已生成独立 bundle ID 的本地预览 App，使用相同代码和核心配置。未替换已安装 App。
- 原生窗口检查被 Mac 锁屏阻止，尚未完成实际窗口视觉核验；未进行 PS5 / Switch 实机测试，也未更改用户网络来测试接管。
