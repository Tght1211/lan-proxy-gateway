# Switch / PS5：连接代理 Wi-Fi

适用于**通过网线上网的 Mac mini / Mac**。Mac 自带 Wi-Fi 用来发热点，不需要另买路由器。设备自动获取 IP、网关和 DNS，不需要挑选空闲地址。

首次配置约分三步，入口在 App 的「设备接入 → 接入设备 → 代理 Wi-Fi」。

## 1. 准备 Wi-Fi（首次设置）

先打开 Mac 的 Wi-Fi 无线功能（Mac 仍通过网线上网）。点击「打开系统共享设置」，进入 macOS 的「通用 → 共享 → 互联网共享」：

- 共享来源选连接家里路由器的以太网。
- 共享给设备的接口选 Wi-Fi。
- 在 Wi-Fi 选项中设置名称、密码，以及游戏机支持的安全方式。
- 设置名称和密码后依次点击「好」「完成」，确认互联网共享开关已打开，再返回 App。App 会自动检测，也可以点击「重新检测」查看最近检测时间。

保存名称和密码不等于热点已经启动。App 会区分 Wi-Fi 电源关闭、配置已保存但服务未启动、共享网络待就绪及地址冲突。若设置已保存但热点未启动，可关闭互联网共享后重新开启。

名称和密码由 macOS 保存；App 不读取密码。首次仍需在系统设置中完成这一步，当前版本不自动操作系统共享开关。

如果 App 提示默认出口不是以太网，请检查网线及 VPN/TUN 的默认路由。无法确认共享网络、发现多个候选网络或地址范围重叠时，App 不会猜测接口。

## 2. 开启热点接管

**代理在本 App 内设置，系统 Wi-Fi 页面没有也不需要 Clash 代理选项。** 已有代理出口时会显示当前地址，无需重复配置。点击「设置代理出口」，填写你已有的 Clash、Mihomo、sing-box 等软件提供的 HTTP/SOCKS5 地址和端口。代理软件需要保持运行。

检测到 Wi-Fi 共享并设置代理出口后，点击「开启热点接管」。系统可能要求管理员授权，用于启动核心和加载设备流量规则。App 会持续显示「未开启 / 正在开启 / 正在确认 / 已开启 / 失败」状态。已有开机自启服务时，会更新该服务使用的核心并保留原来的服务配置，避免重启后仍使用旧版核心。只有运行中核心返回确认，才显示「热点接管已开启」，表示核心已加载规则，**还需要下一步在游戏机上验证**。

这个操作不会替换 Mac 的默认网关、系统 DNS 或系统代理。Mac 与游戏机共用网线带宽、CPU 和内存；不能保证下载、延迟等完全不受资源竞争影响。

## 3. 游戏机连接

| 设备 | 操作 |
|---|---|
| Switch | 系统设置 → 互联网 → 互联网设置 → 选择新 Wi-Fi，输入密码。IP、DNS 选自动，代理服务器不使用。 |
| PS5 | 设置 → 网络 → 设定 → 设定互联网连接 → 选择新 Wi-Fi。IP、DNS 选自动，DHCP 主机名不指定，代理服务器不使用。 |

先运行游戏机的连接测试，再打开商店或下载内容，在 App 的设备列表查看流量。以前手填过地址的设备，请改回自动获取，必要时忘记网络后重新连接。

以后连接这个 Wi-Fi 即可，不需要因 IP 变化重新设置网关和 DNS。IP 变化后，先前按 IP 保存的设备名称或策略可能需要更新；目前不把这些策略当作固定的设备身份。

## 使用期间

- Mac 需要保持开机、唤醒，网线和代理软件保持正常。
- 关闭或重开系统共享后，核心约每 10 秒重新检测热点；检测不到时撤销自己的接管规则，绝不转而接管以太网。重新连接游戏机可清除旧连接和 DNS 缓存。
- 「停止接管」只撤销项目的流量规则，macOS 仍可能提供普通直连网络。要关闭 Wi-Fi，请在系统设置中关闭互联网共享。
- 当前主要代理 TCP；游戏与语音 UDP 仍直连。互联网共享会增加一层 NAT，不能保证改善 Switch NAT 类型或 PS5 联机。热点模式拒绝向外转发 IPv6，以免绕过 IPv4 代理路径。
- 出口仍使用项目原有分流与代理失败回退策略，因此不保证每个连接都经代理。
- 本次实现已做规则、生命周期和自动化测试；PS5 / Switch 的真实热点连接、商店与联机效果仍需在设备上验证。

## CLI（高级）

```bash
gateway hotspot status       # 只读 JSON 检测
gateway egress proxy --type socks5 --host 127.0.0.1 --port 7897
gateway hotspot enable       # 保存模式；不自动开系统热点
sudo gateway restart        # 加载新接入模式

gateway hotspot disable     # 保存停止接管
sudo gateway restart

gateway hotspot use-lan     # 恢复原来的手动网关接入
sudo gateway restart
```

`gateway egress` 仅修改设备流量出口；`gateway system-proxy` 是另一个明确修改 Mac 系统代理的高级命令。

## 实现边界

`gateway.access_mode: hotspot` 使用现有 macOS Internet Sharing 的 DHCP 与 NAT，不新增第二个 DHCP 服务，不修改 `/etc/pf.conf`，也不改变系统 PF/IP 转发的开关状态。防火墙只在检测出的 Wi-Fi 共享网桥及其成员接口、对应 IPv4 来源网段上接管 DNS/TCP，规则放在独立的 `com.apple/000.lan-proxy-gateway` anchor 中。系统互联网共享的规则由 macOS 管理。

热点接口没有就绪时，服务处于等待状态，状态接口不会报告规则已生效。开启状态来自运行中核心的 `stats.hotspot.applied`，不是根据配置文件推测。切换接入模式需要重启；代理出口和分流规则继续支持热更新。

## 分流规则与拓扑

热点接入的 TCP 流量复用 App 中已有的设备策略和域名规则，不生成另一份热点规则。可在接入引导中点击「管理分流规则（共用）」，或在网络总览的「② 共用分流规则」节点编辑；保存后即时应用。上游代理软件仍会执行它自身的规则。

网络总览将当前热点子网内的网关连接显示在「代理 Wi-Fi」节点，其他网关连接和 HTTP 代理单独显示，之后进入同一套策略。热点结果计数来自当前及最近连接记录，不是所选日期范围的历史统计，也不代表应用请求成功。

启用 QUIC 阻止时，UDP/443 必须绕过 fake-IP UDP 重定向，再由过滤规则拒绝，使客户端回退 TCP。其余游戏 UDP 仍按原设计直连；HTTP 上游不提供通用 UDP 代理。

点击拓扑中的「代理 Wi-Fi」可打开快捷面板，查看接管状态和活跃设备、复制热点网关、管理共用规则、打开接入指南或启停代理接管。「查看 Wi-Fi 名称与密码」提供系统共享设置入口与操作说明；不使用可能过期的系统旧配置展示名称，也不缓存密码。修改名称或密码需在系统 Wi-Fi 选项内完成，关闭互联网共享会暂时断开热点设备。
